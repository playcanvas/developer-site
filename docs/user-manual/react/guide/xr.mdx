PlayCanvas React makes it easy to add Virtual Reality (VR) and Augmented Reality (AR) support to your applications using the WebXR API.

## Basic Setup

To enable XR support in your React application, you'll need:

1. **XR Scripts** - Import the XR controller and navigation scripts from the PlayCanvas engine package
2. **Camera Setup** - Configure your camera entity with XR scripts attached
3. **XR Controls** - Add UI buttons to enter and exit XR sessions (WebXR requires user interaction)
4. **Secure Context** - Serve your app over HTTPS (or `localhost` during development)

## XR Scripts

The PlayCanvas engine provides XR scripts for the common jobs. This guide uses three:

- **`XrSession`** - Starts and ends sessions in response to app events, places the camera rig, and makes the camera see-through in AR
- **`XrControllers`** - Automatically downloads and renders XR controller models for detected controllers (including hand tracking)
- **`XrNavigation`** - Implements teleportation-based navigation using point-and-select actions

Import them from the PlayCanvas scripts package:

```tsx
import { XrSession } from 'playcanvas/scripts/esm/xr/xr-session.mjs'
import { XrControllers } from 'playcanvas/scripts/esm/xr/xr-controllers.mjs'
import { XrNavigation } from 'playcanvas/scripts/esm/xr/xr-navigation.mjs'
```

## Camera Configuration

For XR to work properly, you need a camera entity with the XR scripts attached. The recommended structure is:

```tsx
<Entity name="camera-root">
  <Entity name="camera" position={[0, 1.6, 0]}>
    <Camera clearColor="#1e1e1e" />
  </Entity>
  <Script script={XrSession} />
  <Script script={XrControllers} />
  <Script script={XrNavigation} />
</Entity>
```

The camera is positioned at approximately eye-level (1.6 meters) and the scripts are attached to the parent entity, the camera rig. During a session the headset moves the camera within the rig, and moving the rig moves the user. See [Sessions](/user-manual/xr/sessions/#the-camera-and-its-rig).

## Starting XR Sessions

WebXR requires a user gesture to start a session. With `XrSession` on the camera rig, fire its events from a click handler. It starts the session on the camera in its rig, and ends it on `xr:end` or the Escape key:

```tsx
const app = useApp()

const startVR = () => app.fire('vr:start')
const startAR = () => app.fire('ar:start')
const endXR = () => app.fire('xr:end')
```

To request features such as plane detection, start the session on the camera yourself, with `camera.startXr()`. See [Sessions](/user-manual/xr/sessions/#session-features).

## Checking XR Availability

You can check if AR or VR is available on the current device. The engine checks after the application starts, and again when devices change, so keep the answer in state and follow the `available` event:

```tsx
const app = useApp()
const [vrAvailable, setVrAvailable] = useState(false)

useEffect(() => {
  const update = () => setVrAvailable(app.xr.isAvailable('immersive-vr'))
  update()
  const handle = app.xr.on('available', update)
  return () => handle.off()
}, [app])
```

## XR Events

Listen to XR session events to update your UI:

```tsx
useEffect(() => {
  const onStart = () => console.log('XR session started')
  const onEnd = () => console.log('XR session ended')
  
  app.xr.on('start', onStart)
  app.xr.on('end', onEnd)
  
  return () => {
    app.xr.off('start', onStart)
    app.xr.off('end', onEnd)
  }
}, [app])
```
