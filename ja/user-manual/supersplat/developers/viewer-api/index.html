ビューアAPI

createViewerは、自分のページの要素内にSuperSplat Viewerを作成し、それを制御するためのハンドルを返します。自分のウェブアプリがページを管理している場合に使います。たとえば、コンポーネント内でビューアをマウント・アンマウントする、1つのページで複数のビューアを動かす、独自のコントロールでビューアを操作する、UIを置き換える、といった用途です。1つのスプラットを表示するだけのページなら、ビルド済みビューアまたはrenderViewerHtmlのほうが簡単です。

詳細については、パッケージのAPIリファレンスを参照してください。

ビューアの作成​

パッケージとPlayCanvas Engineをインストールします。/viewerエントリポイントはPlayCanvas Engine（バージョン2.24.1以降）をピア依存関係として使うため、ビューアは自分のプロジェクトにインストールしたエンジンの上で動作します：

npm install @playcanvas/supersplat-viewer playcanvas
import { createViewer } from '@playcanvas/supersplat-viewer/viewer';
import '@playcanvas/supersplat-viewer/viewer.css';

const viewer = await createViewer({
    container: document.getElementById('viewer'),   // サイズは自分で指定し、ビューアはその全体を使います
    settings: './settings.json',                    // URL、設定オブジェクト、またはそのPromise
    contentUrl: './scene.sog',
    posterUrl: './poster.jpg'                       // 省略可能
});

ビューアはコンテナ内に独自のキャンバス、UI、アイコンを構築するため、コンテナには必ずサイズを指定してください。高さのない要素では何もレンダリングされません。

createViewerは、シーンが表示されたときではなく、グラフィックスデバイスが作成されて読み込みが始まった時点で解決されます。カメラ、再生、注釈のコマンドを呼び出す前に、loadedを待ってください：

viewer.events.on('progress:changed', (progress) => console.log(`${progress}%`));
viewer.events.on('loaded:changed', () => console.log('first frame rendered'));

オプション​

オプション説明
containerビューアが自身を構築する要素。必須です。
settingsExperience Settings：URL、サポートされている任意のバージョンのオブジェクト、またはそのPromise。必須です。
contentUrl読み込むスプラット。必須です。対応フォーマットであれば何でもよく、data: URIも使えます。
contentFilenamescene.sogのような、コンテンツの名前。フォーマットは名前の拡張子から判断されるため、contentUrlに使える名前がない場合（data: URIなど）に設定します。
posterUrl / posterスプラットの読み込み中にぼかして表示する画像。URL、または作成済みのHTMLImageElementで指定します。
skyboxUrlエクイレクタンギュラースカイボックス画像。
collisionUrlウォークモード用のコリジョンデータ：.glbメッシュ、またはボクセルデータ。
contentsすでに開始しているfetch（contentUrlを取得するもの）。ビューアのコードが届く前にダウンロードを開始できます。
zstdDecoderUrlバージョン4の.spzのデコーダーの読み込み元。デコーダーファイルを参照してください。

残りのオプションはURLパラメータをプログラムから指定するためのもので、名前も同じです。ただし、次の例外があります：

  • renderer: 'webgl'は、webglと同様にWebGLを強制します。デフォルトは'webgpu'で、WebGPUが利用できない環境ではWebGLにフォールバックします。
  • ui: falseは、nouiと同様に組み込みUIを省きます。UIの置き換えを参照してください。
  • exposeGlobals: trueは、ビューアのwindow.app、window.captureFrameなどのフックを公開します。ページに複数のビューアがある場合はオフのままにしてください。

createViewerはページのURLを読み取りません。すべてのオプションを自分で渡してください。

ビューアハンドル​

メンバー用途
stateビューアの監視可能な状態。
events<key>:changedイベントを(value, previous)を引数として発火します。対象はstateのすべてのキーです。
annotationsシーンの注釈（設定内の順序）。読み取り専用です。
captureFrame(options?)静止画をオフスクリーンでスーパーサンプリングしてレンダリングし、{ width, height, data }（dataはbase64）で解決されます。オプション：time、width（デフォルト480）、height、supersample（デフォルト2）。
seek(time)アニメーションを指定した秒数の位置にシークします。一時停止状態は維持されます。
frameScene()オービットモードでシーン全体をフレーミングします。
resetCamera()フライモードまたはウォークモードでは、そのモードに入った位置に戻ります。それ以外では、オービットモードで開始時のビューを復元します。
toggleWalk()ウォークモードに入るか、直前のモードに戻ります。state.walkAllowedでない場合は何もしません。
selectAnnotation(index)0から始まるインデックスで注釈を選択し、カメラをその注釈に移動します。nullを渡すと、カメラを動かさずに選択を解除します。
setMoveInput(x, z)カスタムジョイスティック向けに、フライモードまたはウォークモードでカメラ基準の移動入力を保持します。xが正なら右、zが正なら前で、それぞれ-1から1の範囲です。停止するには(0, 0)を送ります。
requestFullscreen() / exitFullscreen()このビューアのフルスクリーン表示を開始・終了します。
startXR(mode) / endXR()modeに'ar'または'vr'を指定して没入型セッションを開始するか、セッションを終了します。
destroy()エンジンアプリケーション、グラフィックスコンテキスト、すべてのリスナー、ビューアの要素を解放します。複数回呼び出しても、読み込みの完了前に呼び出しても安全です。
app内部のPlayCanvasアプリケーション。このAPIでカバーされていない操作に使います。

カメラ、再生、注釈、移動のコマンドは、state.loadedより前とdestroy()の後に呼び出すと例外をスローします。フルスクリーンとXRのコマンドはPromiseを返します。フルスクリーンやセッションを開始するコマンドは、クリックなどのユーザージェスチャーから呼び出し、拒否された場合の処理も行ってください。

状態​

書き込み可能なキーに値を書き込むと、変更はすぐに反映され、組み込みUIもそれに従います。読み取り専用のキーは、ビューアが検出した内容や実行中の処理を報告します。

キー書き込み可説明
loaded最初の完全なフレームがレンダリングされるとtrueになります。
progress読み込みの進捗（0～100）。
cameraMode✓'orbit'、'fly'、'walk'、'anim'（カメラアニメーション）のいずれか。
walkAllowedウォークモードを利用できるかどうか。コリジョンデータと、幅が5 m以上のシーンが必要です。
hasCollisionコリジョンデータが読み込まれたかどうか。
hasCollisionOverlayコリジョンをオーバーレイとして描画できるかどうか。
collisionOverlayEnabled✓コリジョンオーバーレイを描画します。
hasAnimation再生できるカメラアニメーションがあるかどうか。
animationPaused✓再生が一時停止しているかどうか。
animationTime / animationDuration再生ヘッドの位置と長さ（秒）。
selectedAnnotation選択中の注釈のインデックス、またはnull。変更するにはselectAnnotation()を使います。
showAnnotations✓組み込みのホットスポットを表示します。保存されます。
quality✓Qualityの段階：'performance'、'default'、'high'、'max'のいずれか。保存されます。
qualityAvailableこのデバイスで使える段階。
performanceMode✓Performance Mode。保存されます。
gamingControls✓Gaming Controls。保存されます。
iceCream✓XRでのアイスクリームモード。保存されます。
inputMode'desktop'または'touch'：訪問者が最後に使った入力方法。
controlsHidden✓組み込みのコントロールを非表示にします。操作がない間は、ビューアもこの値を設定します。
inputEnabled✓このビューアがキーボードとゲームパッドの入力を受け付けるかどうか。
isFullscreenこのビューアがフルスクリーン表示かどうか。
hasAR / hasVRARまたはVRセッションを開始できるかどうか（今すぐ、またはWebGLで再読み込みした後）。
canStartAR / canStartVR現在のレンダラーでセッションを開始できるかどうか。
xrMode'ar'、'vr'、またはnull。

コリジョンデータはシーンが表示された後に届くため、walkAllowedとhasCollisionはloadedの後に変わることがあります。一度だけ読み取るのではなく、変更イベントを監視してください。

保存される設定​

quality、performanceMode、gamingControls、showAnnotations、iceCreamは、ブラウザのローカルストレージから読み込まれ、そこに保存されます。キーは、サイトのオリジン上のすべてのビューアで共有されます。新しいビューアは保存された値を読み込みますが、すでにページ上にあるビューアは自身の値を維持します。組み込みUIは、コントロールパネルが開いているかどうかも記憶します。ストレージがブロックされている場合、ビューアはデフォルト値で動作します。

ビューアの制御​

組み込みのコントロールは自分のコードと同じコマンドを使うため、両者は常に同期します。まずloadedを待ちます：

const whenLoaded = (callback: () => void) => {
    if (viewer.state.loaded) callback();
    else viewer.events.once('loaded:changed', callback);
};

再生​

// 3秒の位置で停止
whenLoaded(() => {
    viewer.state.animationPaused = true;
    viewer.seek(3);
});

// どのカメラモードからでも再開
viewer.state.cameraMode = 'anim';
viewer.state.animationPaused = false;

seek()は、繰り返すトラックでは時間を折り返し、それ以外のトラックでは長さの範囲内に収めます。

カメラ​

オービット、フライ、アニメーションを切り替えるには、state.cameraModeを設定します。ウォークモードにする前にはstate.walkAllowedを確認するか、直前のモードへの復帰も行うtoggleWalk()を呼び出します。frameScene()とresetCamera()は、カメラの移動を開始してすぐに戻ります。

独自の方向コントロールを作る場合は、フライモードまたはウォークモードを選択してから、コントロールが離されるまでsetMoveInput()で移動入力を保持します：

viewer.state.cameraMode = 'fly';
viewer.setMoveInput(0, 1);    // 前進

// 離したとき、pointercancelのとき、またはアンマウント時：
viewer.setMoveInput(0, 0);

注釈​

viewer.events.on('selectedAnnotation:changed', (index) => {
    const annotation = index === null ? null : viewer.annotations[index];
    console.log(annotation?.title);
});

whenLoaded(() => {
    if (viewer.annotations.length) viewer.selectAnnotation(0);
});

注釈を選択するとオービットモードに切り替わり、アニメーションの一時停止状態を変えずに、カメラが注釈のビューへ移動します。state.showAnnotationsで組み込みのホットスポットを非表示にしても、選択は解除されません。

フルスクリーンとXR​

fullscreenButton.addEventListener('click', () => {
    viewer.requestFullscreen().catch(showError);
});
vrButton.addEventListener('click', () => {
    viewer.startXR('vr').catch(showError);
});
viewer.events.on('xrMode:changed', updateControls);

機能のチェックはビューアの作成後に完了することがあるため、state.canStartARとstate.canStartVRを確認し、それらの変更イベントも購読してください。startXR()は、現在のレンダラーでセッションを実行できない場合に拒否されます。ページを再読み込みすることはありません。

組み込みのWebGL Requiredダイアログは、?webglを追加してページを再読み込みします。自分のページでビューアを作成し、組み込みUIを使い続ける場合は、そのパラメータを読み取ってrenderer: 'webgl'を渡してください。セッション中に訪問者ができることについては、VRとARでの表示を参照してください。

スタイルの変更​

組み込みUIが使う色は、ビューアのルート要素に設定されたCSSカスタムプロパティなので、何も置き換えずにテーマを変更できます：

#viewer .sse-viewer {
    --sse-accent: #09f;     /* ハイライト、アクティブなトグル、タイムライン */
    --sse-bkg: #204;        /* パネル。半透明の面はこの色から派生します */
    --sse-text-light: #fff;
}

すべてのプロパティは--sse-text、--sse-text-light、--sse-text-dark、--sse-text-darkest、--sse-accent、--sse-grip、--sse-bkg、--sse-bkg-dark、--sse-bkg-darkest、--sse-bkg-lightです。ビューアのその他のクラス名はAPIの一部ではなく、リリースごとに変わります。

UIの置き換え​

ui: falseを渡すと、キャンバスだけが作成されます。キャンバス上のカメラ入力、キーボードとゲームパッドの入力、保存される設定は引き続き機能しますが、ツールバー、パネル、ポスター、ローディングバー、注釈のホットスポットとナビゲータは含まれません。ハンドルとその状態を使って、独自のコントロールを構築してください。タッチジョイスティック、フルスクリーンボタン、WebGL Requiredダイアログも置き換えるUIの一部なので、これらも自分で用意する必要があります。代わりのジョイスティックにはsetMoveInput()を使えます。組み込みUIの一部だけを置き換えることはできません。

ビューアのリポジトリにあるカスタムUIの例では、読み込み、再生、カメラモード、移動、注釈、設定、フルスクリーン、XRを、ハンドルだけで操作しています。

1ページ内の複数のビューア​

各ビューアは独自の要素と独自のエンジンアプリケーションを持ちます。windowには、exposeGlobalsを設定しない限り何も公開されません。キーボードとゲームパッドの入力はポインターの位置によって振り分けることができないため、入力を無視すべきビューアや、自分のフォームフィールドにフォーカスがある間は、state.inputEnabledをオフにしてください。

不要になったビューアでは、必ずdestroy()を呼び出してください。ブラウザは有効なWebGLコンテキストの数を16前後に制限しているため、ビューアを破棄せずにマウントとアンマウントを繰り返すコンポーネントは、やがてレンダリングできなくなります。

デコーダーファイル​

バージョン4の.spzファイル（単体、または.lcc2シーンのチャンク）には、WebAssemblyデコーダーのzstd-decoder.wasmが必要です。これはビューアのバンドルと一緒に配布され、該当するコンテンツを読み込むときにのみ取得されます。new URL(…, import.meta.url)を処理できるバンドラーは、これをバンドルと一緒に出力します。そうでない場合は、バンドルと同じ場所にapplication/wasmとして配信するか、zstdDecoderUrlでその場所を指定してください。このデコーダーはblob: URLから読み込まれるため、Content-Security-Policyでblob:スクリプトを許可する必要があります。
